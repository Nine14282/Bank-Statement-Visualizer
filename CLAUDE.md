# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Statement Visualizer: bank-statement PDFs (Krungthai/KTB and Kasikorn/KBank) → merged `workspace/ledger.csv` → the dashboard `web/dist/index.html` (React app built to one self-contained file; opens offline, nothing uploaded). Meant to be open source and run locally by anyone. Pipeline is plain Python scripts (no test suite, no linter; two self-checks below); `web/` is a Vite app with `tsc` + `oxlint` only (no tests). Statement text is Thai; KTB dates are Buddhist-era `DD/MM/YY`, KBank dates Christian-era `DD-MM-YY`. UI/UX rules (tokens, fonts, components, motion): see `DESIGN.md`.

## Commands

Run from anywhere (scripts anchor paths to their own folder). Use the project venv: `.venv/bin/python`.

```bash
./install.sh                                       # the user-facing install: runs setup.sh with SV_NO_OPEN=1, so nothing opens
./setup.sh                                         # once: venv + requirements.txt + .env from .env.example (adds new keys to an existing .env); no Node needed
./run.sh                                           # use case 1: first run (no ledger.csv) installs what's missing and opens the setup page; later runs open the "add statements" page (welcome.py --add)
./run.sh --setup                                   # open the full setup page again (workspace/welcome.py)
./run.sh --rebuild                                 # terminal rebuild from Statement/*.pdf, no browser (also with --password=, or when stdin isn't a terminal, e.g. cron)
./gmail.sh                                         # use case 2 (auto): Gmail -> Statement/ -> dashboard; cron-friendly
./uninstall.sh [--all] [-y] [-n]                    # remove launcher, .venv, node_modules, generated dashboard (--all: the whole folder, data included; -n = dry run)
.venv/bin/python workspace/update_statement.py     # main entry: Statement/*.pdf -> ledger.csv -> web/dist/index.html
KTB_PW=xxxx KBANK_PW=yyyy .venv/bin/python workspace/update_statement.py   # unattended (else prompts; also --password=)
.venv/bin/python workspace/fetch_gmail.py          # pull new statement PDFs + payment-notice emails from Gmail, then update (--no-build to skip)
.venv/bin/python workspace/app.py                  # the app window (pywebview); ./run.sh and the launcher start it; exits 3 when no web view is available
.venv/bin/python workspace/build_dashboard.py      # rebuild dashboard only: ledger.csv -> data injected into web/prebuilt/index.html -> web/dist/index.html (Python only)
.venv/bin/python workspace/build_dashboard.py --selfcheck   # data-injection self-check (hostile text can't escape the data tag)
.venv/bin/python workspace/extract_ledger.py IN.pdf OUT.csv   # parse a single PDF (any registered bank)
.venv/bin/python workspace/extract_ledger.py --selfcheck      # parser self-check (interest rule, KBank direction + CHECK reporting)
.venv/bin/python workspace/txid.py                 # transaction-ID self-check
cd web && npm install && npm run dev               # developers only (Node 22.12+ or 20.19+, Vite 8's floor): live UI with the data from src/data/ledger.json (written by build_dashboard.py)
cd web && npm run build                            # developers only: tsc -b + vite build -> web/prebuilt/index.html (no data; commit it with any web/src change)
cd web && npm run lint                             # oxlint; 3 known warnings in generated src/components/ui/{badge,button,toggle}.tsx
```

## Architecture

Pipeline, in order:

1. `fetch_gmail.py` — Gmail API (read-only scope) over plain HTTPS: `google.auth.transport.requests.AuthorizedSession` + 3 GETs (list/get/attachment) with urllib3 retry on 429/5xx, not google-api-python-client (its API discovery cache alone is ~100 MB); a cron run with no valid token exits instead of opening a browser; `--selfcheck` runs against a fake session. Statement emails (query `GMAIL_QUERY`) → PDFs saved as `Statement/<msgid8>_<name>.pdf`; Krungthai NEXT payment-notice emails → rows appended to `workspace/manual_entries.csv` (description contains `(email)`). Processed message ids tracked in `workspace/.gmail_seen.json`. OAuth: `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` (and `GOOGLE_PROJECT_ID`, optional `GMAIL_QUERY`) come from the project-root settings file via `workspace/config.py` (shared tiny loader, imported first by every script; real env vars win, blank values count as unset; no python-dotenv; `config.save()` writes a key back with mode 0600; all settings documented in `.env.example`); cached `token.json` in `workspace/`. `.env` and `token.json` are secrets — never print/commit (both git-excluded).
2. `extract_ledger.py` — bank registry `BANKS` (one `Bank(id, name, password settings, file-name pattern, page-1 markers, parser)` per bank; passwords, detection, `build_dashboard`'s secret list and the setup page all read it). KTB parser: `pdfplumber` word positions; debit vs credit by the amount's **x-centre** (`WD_MAX=400`, `DEP_MAX=470`), not by text; branch column is `x0 > 540`; a row starts at a date token and following lines attach to it; counts/sums checked against the statement's printed totals; interest rows move to 23:59 so balances chain. KBank parser: direction from the running balance, cross-checked with position and printed totals. A row that doesn't reconcile prints `CHECK <file>: ...` and is **still imported** (never dropped). `categorize()` maps reference numbers (`LEDGER_CASH_REF`/`LEDGER_PEER_REF`/`LEDGER_STOCK_REF` in the settings; blank = off; categories are baked into `ledger.csv` at extraction, so a new ref only shows after the next re-extract) + money direction to categories, falling back to `TYPE_EN` (Thai type prefix → English).
3. `update_statement.py` — merges all PDFs. `candidates()` tries for each file: no password, its own bank's settings (by file name), every other bank's, then `--password=` / typed ones; non-interactive runs exit instead of prompting. Dedupes by transaction ID (`txid.py`); same ID with only new wording takes the newer description. Appends `workspace/manual_entries.csv` (hand-entered spends and Gmail notices; blank Balance; a notice is dropped when a KTB statement row of the same amount is within 4h, 6h for "Future Amount" rows, which then take the notice's time). Marks pairs across banks as `Own transfer` (excluded from income/expense). Sorts, writes `ledger.csv`, then calls `build_dashboard.build()`. Two copies of one ID that disagree on balance are printed as `CONFLICT` (earlier copy kept). Refuses to overwrite `ledger.csv` if zero rows were read.
4. `build_dashboard.py` — prints the ledger.csv summary and `find_gaps()` warnings, builds the payload `{meta: {account,name,from,to,n,gaps,theme,plan}, tx: [...]}`, and writes `web/dist/index.html` = the committed `web/prebuilt/index.html` with the payload replacing its `<script id="ledger-data" type="application/json">null</script>` placeholder (`MARK`, also in `web/index.html` and `web/vite.config.ts`; every `<` in the JSON escaped as `<`), plus `web/dist/version.js`. No Node/npm at runtime. It also writes `web/src/data/ledger.json` for the dev server only. `find_gaps()` flags empty months and balance jumps per bank (rows chained by balance within the same minute; offsetting nearby jumps are dropped as out-of-order posting); the React app only displays `meta.gaps`. Manual rows (`bal is None`) are skipped for balance chaining.

`welcome.py` — page server started by `./run.sh`: full setup on the first run (no `ledger.csv`) or `--setup`; the short "add statements" page (`--add`) on later interactive runs. Serves the built page at `/?setup` (`/?setup&add` in add mode; React `Wizard` picks its steps from that) on 127.0.0.1, random port; printed one-time token → HttpOnly SameSite=Strict cookie, every API call also needs the `X-Setup` header. It saves uploads into `Statement/`, checks each bank's password by parsing its files (optionally saving it to `.env`), writes `THEME` / `workspace/expected.json` only when the page sends them (setup mode; the add page sends neither), builds, then stops. It blocks until finished; `./run.sh` falls back to the terminal rebuild when stdin isn't a terminal, but a fresh checkout (no ledger) still opens setup, so cron uses `./gmail.sh`. `python welcome.py --selfcheck` checks file-name and spending-list cleaning. `update_statement.py` keeps a per-PDF parse cache in `workspace/.cache/` (key = file bytes + `extract_ledger.py` source + pdfplumber version + the `LEDGER_*_REF` settings; mode 0600; unused entries pruned after each good run; `update_statement.py --selfcheck` covers it and the same-minute sort order).

`app.py` — the app window `./run.sh` / `./run.sh --app` opens: `web/dist/index.html` in the system web view via pywebview (GTK/WebKit2 on Linux, forced with `gui="gtk"`; its saved page state lives in `workspace/.app/` on Linux only, macOS uses WebKit's default store). Add statements / Settings open the setup page inside the window; its `Api.call` runs the same `welcome.handle` handlers as the HTTP server (rescanning `Statement/` per call). No web view → exit 3 and `run.sh` opens the browser pages. `run.sh` rebuilds `web/dist` before every launch and re-runs `setup.sh` when `requirements.txt` differs from `.venv/requirements.installed` (written after a good install).

Adding a bank: a `Bank(...)` entry + parser in `extract_ledger.py`, and a display entry (name, card colour, logo) in `web/src/lib/banks.ts`. Adding a theme: an entry in `web/src/lib/themes.ts` + optional `[data-theme="…"]` block in `web/src/index.css`.

## Gotchas

- `web/dist/index.html` is generated and holds all the data inline; never edit it. Edit `web/src/`, then `npm run build` (refreshes `web/prebuilt/index.html`) and `build_dashboard.py` (puts the data in).
- Personal data is gitignored (`workspace/*.csv`, `workspace/expected.json`, `workspace/.cache/` (parsed rows per PDF), `workspace/.app/` (the app window's browser storage), `web/src/data/`, `Statement/`, `token.json`, `workspace/.gmail_seen.json`, the env secrets file; `web/dist` via `web/.gitignore`). No personal values live in code, docs or defaults: account refs, `ACCOUNT_LABEL`/`ACCOUNT_HOLDER` (top-bar avatar + greeting) and `THEME` come from the settings file; keep it that way. Passwords: `KTB_PW` (old name `STATEMENT_PW` still read) and `KBANK_PW`. README.md is the user-facing guide (setup page + two use cases); keep it in sync with the scripts. A global hook blocks Claude from touching env files.
- Ledger CSVs are `utf-8-sig`; columns `Date, Description, Category, Amount, Balance, ID, Bank` (`KTB`/`KBANK`/`Manual`); Amount signed (income +, expense −). `manual_entries.csv` keeps the first five (ID and Bank are set on merge). An old 6-column ledger gets `Bank` on the next `./run.sh`.
- Transaction ID (`workspace/txid.py`, `python txid.py` is its self-check): sha256 (16 hex) of `yyyymmdd hhmm <satang>#<n>` (rows of banks other than KTB/Manual get the bank name in front, so a KTB and a KBank payment never share an ID); money out has a leading 0 (`0100` = out 1.00, `100` = in 1.00); `n` = occurrence of the same (minute, signed amount) within ONE statement. The `n` matters: real data has repeated same-minute same-amount transactions (e.g. four 30 baht deposits in one minute), which a plain date+time+amount key would silently drop. Overlapping statements number the same rows the same way, so their copies share IDs. A hash collision raises.
- Directories `Statement/`, `workspace/`, `web/` and `.venv/` are the whole project (`web/node_modules` and `web/dist` are build output; `web/prebuilt/index.html` is build output too but committed on purpose, so users need no Node). The project folder is its own git repo.
- After any change under `web/src/` (or `web/index.html`, `vite.config.ts`), run `npm run build` and include `web/prebuilt/index.html` in the same commit; otherwise users keep running the old page. It must never contain data: the ledger only ever enters through the placeholder.

## web/ (React dashboard)

Vite 8 + React 19 + TypeScript 6 + Tailwind v4 + shadcn/ui (style `base-nova`, Base UI primitives) + Recharts + Motion (`motion/react`), plus MUI 9 pieces (Drawer, Popover, Tooltip, Snackbar, Pagination, Avatar, Badge, Chip, IconButton, LinearProgress, Divider, Typography). `vite-plugin-singlefile` inlines everything into one offline page (`prebuilt/index.html`, no data; `publicDir` is off). Full design system in `DESIGN.md`.

- All aggregation is in `src/lib/ledger.ts` (`summarize`, `rateTable`, formatters). Components live in `src/components/ledger/`, the setup wizard in `src/components/setup/wizard.tsx`, entry `src/App.tsx` (`/?setup` → `Wizard`, else dashboard). Three tabs in the URL hash (Dashboard, `#plan` Expected Spending, `#custom` labels); the dashboard is one page whose nav rail scrolls to sections (`SECTIONS` in `src/lib/nav.ts`).
- Browser-local state (localStorage): `ledger-label-rules` (Custom tab labels; saving reloads the page), `ledger-expected-spending`, `ledger-theme`, `ledger-seen-rows` (new-row highlight). The wizard's `THEME`/`expected.json` arrive via `meta` and seed these defaults.
- Styling: `src/index.css` holds theme tokens (dark "Midnight" default, light "Daylight"; violet `--brand` for controls, violet `--income` / coral `--expense` for data, green/red `--pos`/`--neg` for signed amounts) and helpers `.display`, `.eyebrow`, `.pill`, `.num`. Fonts via `@font-face`: Geist, Geist Mono (woff2 vendored in `src/assets/fonts/` with their OFL licence; the `geist` npm package was dropped because its `next` peer dependency pulled ~300 MB of Next.js into every install), Outfit (display/headings, `@fontsource-variable/outfit`). First line of `index.css` sets `@layer ... mui ...` so MUI sits below Tailwind utilities; MUI colour mode drives the Tailwind `.dark` class (`src/lib/mui-theme.ts`, `src/lib/themes.ts`, `main.tsx`).
- `src/components/ui/*` is shadcn-generated (`card.tsx` customised); `@/lib/utils` is `cn` (clsx + tailwind-merge). Do not add the npm package `cn`; the shadcn CLI emitted `from "cn"` imports once and they had to be rewritten. The `shadcn` package is not a dependency (its CLI drags in ts-morph, an MCP SDK, …): its `tailwind.css` is vendored as `src/shadcn.css`; add components with `npx shadcn@latest add <name>`. Don't re-add `shadcn` or `geist` to package.json.
- `TxTable` mounts either the table or the card list by media query, never both (rendering both froze the browser), and pages 15 rows at a time.
- Each `build_dashboard.py` run writes `dist/version.js`; an open page polls it every 10s and reloads after a rebuild.
- Keep `data-od-id` tags on main regions. Dark mode is the default, light must keep working.
- Empty ledger is a supported state: `lib/ledger.ts` reads the data from the `#ledger-data` tag at runtime (`null`, the untouched placeholder, = empty dataset) and `App` renders `EmptyState` when `TX` is empty. `build_dashboard.py` and `setup.sh` build that blank page without any CSV. Never import `@/data/ledger.json` (it would bundle personal data into the committed prebuilt page), and keep anything that reads `TX[0]`/`META.from` inside `Dashboard`.
