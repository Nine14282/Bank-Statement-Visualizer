# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Statement Visualizer: bank-statement PDFs (Krungthai/KTB and Kasikorn/KBank) → merged `workspace/ledger.csv` → the dashboard `web/dist/index.html` (React app built to one self-contained file; opens offline, nothing uploaded). Meant to be open source and run locally by anyone. Pipeline is plain Python scripts, with standard dev tooling around them: uv (`pyproject.toml` + `uv.lock`), ruff, pytest (`tests/`), pre-commit and CI (`.github/workflows/ci.yml`); `web/` is a Vite app with `tsc` + `oxlint` + Vitest. End users never need uv: they install with pip from the generated `requirements*.txt`. Statement text is Thai; KTB dates are Buddhist-era `DD/MM/YY`, KBank dates Christian-era `DD-MM-YY`. UI/UX rules (tokens, fonts, components, motion): see `DESIGN.md`.

## Commands

Run from anywhere (scripts anchor paths to their own folder). Use the project venv: `.venv/bin/python`.

```bash
./install.sh                                       # the user-facing install (workspace/launcher.py install): nothing opens
./setup.sh                                         # the same (launcher.py setup), then opens the app. Both: .venv + pip install -r requirements.txt (+ requirements-app.txt for the app window) + the settings file from .env.example (adds new keys to an existing one); no Node needed
./run.sh                                           # use case 1: opens the app (installs what's missing first); no app window possible -> the same app in the browser (welcome.py)
./run.sh --setup                                   # only the full setup page, in the browser (welcome.py --setup)
./run.sh --rebuild                                 # terminal rebuild from Statement/*.pdf, no browser (also with --password=, or when stdin isn't a terminal, e.g. cron)
./gmail.sh                                         # use case 2 (auto): Gmail -> Statement/ -> dashboard; cron-friendly
./uninstall.sh [--all] [-y] [-n]                    # remove launcher, .venv, node_modules, generated dashboard (--all: the whole folder, data included; -n = dry run)
.venv/bin/python workspace/update_statement.py     # main entry: Statement/*.pdf -> ledger.csv -> web/dist/index.html
KTB_PW=xxxx KBANK_PW=yyyy .venv/bin/python workspace/update_statement.py   # unattended (else prompts; also --password=)
.venv/bin/python workspace/fetch_gmail.py          # pull new statement PDFs + payment-notice emails from Gmail, then update (--no-build to skip)
.venv/bin/python workspace/app.py                  # the app window (pywebview); ./run.sh and the launcher start it; exits 3 when no web view is available
.venv/bin/python workspace/build_dashboard.py      # rebuild dashboard only: ledger.csv -> data injected into web/prebuilt/index.html -> web/dist/index.html (Python only)
.venv/bin/python workspace/extract_ledger.py IN.pdf OUT.csv   # parse a single PDF (any registered bank)
cd web && npm install && npm run dev               # developers only (Node 22.12+: Vitest 5's floor; Vite 8 alone also runs on 20.19+): live UI with the data from src/data/ledger.json (written by build_dashboard.py)
cd web && npm run build                            # developers only: tsc -b + vite build -> web/prebuilt/index.html (no data; commit it with any web/src change)
cd web && npm run lint                             # oxlint; 3 known warnings in generated src/components/ui/{badge,button,toggle}.tsx
cd web && npm test                                 # Vitest, watch mode (src/lib/ledger.test.ts: the ledger maths); `npx vitest run` = one run, what CI does
```

Developer tooling (all config in `pyproject.toml`; uv 0.11.26 is pinned by `[tool.uv] required-version`). Careful: plain `uv sync` makes `.venv` match the lock without the app extra and removes PyQt6/pywebview from the app's `.venv`, and the launcher would not notice; use `--extra app`, or point `UV_PROJECT_ENVIRONMENT` at another folder.

```bash
uv sync --extra app                                # dev tools + the app's packages into .venv
uv run pytest                                      # all Python tests (tests/test_*.py, one file per module); they run in a temp root (SV_ROOT, see Gotchas)
uv run pytest tests/test_ktb.py tests/test_kbank.py tests/test_extract_ledger.py   # the parsers only
uv run ruff check                                  # lint (--fix to apply); rules and per-file ignores in pyproject.toml
uv run ruff format workspace tests                 # format (--check = what CI / pre-commit do)
uv run pre-commit install                          # once: ruff, file hygiene and the uv lock/export hooks run on every commit
uv run pre-commit run --all-files                  # what the CI "quality" job runs; a stale lock or export shows up as a file the hook modified
uv lock                                            # after editing pyproject.toml; then regenerate the two pip files (the hooks do it too):
uv export --frozen --no-dev --no-emit-project --quiet --output-file=requirements.txt
uv export --frozen --no-dev --no-emit-project --quiet --extra=app --output-file=requirements-app.txt
UV_PROJECT_ENVIRONMENT=build-venv uv sync --locked --no-dev --group build   # Windows program: then `UV_PROJECT_ENVIRONMENT=build-venv uv run --no-sync pyinstaller --clean --noconfirm statement-visualizer.spec`
StatementVisualizer.exe --smoke                    # the built Windows program only: imports every config.SCRIPTS module + pdfplumber, Google sign-in, webview; prints "smoke ok" (CI runs it)
```

## Architecture

Pipeline, in order:

1. `fetch_gmail.py` — Gmail API (read-only scope) over plain HTTPS: `google.auth.transport.requests.AuthorizedSession` + 3 GETs (list/get/attachment) with urllib3 retry on 429/5xx, not google-api-python-client (its API discovery cache alone is ~100 MB); a cron run with no valid token exits instead of opening a browser; `tests/test_fetch_gmail.py` runs against a fake session. Statement emails (a fixed sender/subject query per bank, in `workspace/banks/`) → PDFs saved as `Statement/<msgid8>_<name>.pdf`; Krungthai NEXT payment-notice emails → rows appended to `workspace/manual_entries.csv` (description contains `(email)`). Processed message ids tracked in `workspace/.gmail_seen.json`. OAuth: `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` (and `GOOGLE_PROJECT_ID`) come from the project-root settings file via `workspace/config.py` (shared tiny loader, imported first by every script; real env vars win, blank values count as unset; no python-dotenv; `config.save()` writes a key back with mode 0600; all settings documented in `.env.example`); cached `token.json` in `workspace/`. `.env` and `token.json` are secrets — never print/commit (both git-excluded).
2. `extract_ledger.py` — picks the bank for a PDF and writes the CSV; the registry `BANKS` is in `workspace/banks/` (one module per bank with its `Bank(id, name, password settings, file-name pattern, page-1 markers, parser, ...)` record, no self-check field; passwords, detection, `build_dashboard`'s secret list and the setup page all read it). KTB parser (`banks/ktb.py`): `pdfplumber` word positions; debit vs credit by the amount's **x-centre** (`WD_MAX=400`, `DEP_MAX=470`), not by text; branch column is `x0 > 540`; a row starts at a date token and following lines attach to it; counts/sums checked against the statement's printed totals; interest rows move to 23:59 so balances chain. KBank parser (`banks/kbank.py`): direction from the running balance, cross-checked with position and printed totals. A row that doesn't reconcile prints `CHECK <file>: ...` and is **still imported** (never dropped). `categorize()` maps reference numbers (`LEDGER_CASH_REF`/`LEDGER_PEER_REF`/`LEDGER_STOCK_REF` in the settings; blank = off; categories are baked into `ledger.csv` at extraction, so a new ref only shows after the next re-extract) + money direction to categories, falling back to `TYPE_EN` (Thai type prefix → English).
3. `update_statement.py` — merges all PDFs. `candidates()` tries for each file: no password, its own bank's settings (by file name), every other bank's, then `--password=` / typed ones; non-interactive runs exit instead of prompting. Dedupes by transaction ID (`txid.py`); same ID with only new wording takes the newer description. Appends `workspace/manual_entries.csv` (hand-entered spends and Gmail notices; blank Balance; a notice is dropped when a KTB statement row of the same amount is within 4h, 6h for "Future Amount" rows, which then take the notice's time). Marks pairs across banks as `Own transfer` (excluded from income/expense). Sorts, writes `ledger.csv`, then calls `build_dashboard.build()`. Two copies of one ID that disagree on balance are printed as `CONFLICT` (earlier copy kept). Refuses to overwrite `ledger.csv` if zero rows were read.
4. `build_dashboard.py` — prints the ledger.csv summary and `find_gaps()` warnings, builds the payload `{meta: {account,name,from,to,n,gaps,theme,plan}, tx: [...]}`, and writes `web/dist/index.html` = the committed `web/prebuilt/index.html` with the payload replacing its `<script id="ledger-data" type="application/json">null</script>` placeholder (`MARK`, also in `web/index.html` and `web/vite.config.ts`; every `<` in the JSON escaped as `<`), plus `web/dist/version.js`. No Node/npm at runtime. It also writes `web/src/data/ledger.json` for the dev server only. `find_gaps()` flags empty months and balance jumps per bank (rows chained by balance within the same minute; offsetting nearby jumps are dropped as out-of-order posting); the React app only displays `meta.gaps`. Manual rows (`bal is None`) are skipped for balance chaining.

`welcome.py` — the app in the browser, started by `./run.sh` when no app window is possible (app.py exit 3) or in `--web` mode: serves the dashboard at `/?web` (Add statements and Settings work in the page over HTTP; with no ledger it shows the first-time setup), or with `--setup` only the full setup at `/?setup` (stops after its build and opens the dashboard). 127.0.0.1, fixed port 47613 (a browser keeps localStorage per origin; random port if taken); printed one-time token → HttpOnly SameSite=Strict cookie, every API call also needs the `X-Setup` header. The page pings `/api/ping` every 30 s; the server stops after 3 min without a request (`IDLE`). It saves uploads into `Statement/` (rescanned per request), checks each bank's password by parsing its files (optionally saving it to `.env`), saves the Gmail settings (`/api/google`, validated; blank secret keeps the saved one), opens the data folder (`/api/folder`), deletes all data (`/api/clear` = `launcher.py clear -y --in-app`, needs `confirm: "DELETE"`, then the app closes), and writes `workspace/expected.json` only when the page sends it (setup mode; the add page doesn't; the setup has no theme step, `THEME` is only set by hand). Statements can be removed one by one; one that was already in `Statement/` needs `confirm: true` (the page asks first). Gmail keys and the folder path show as dots until Show is confirmed (`Reveal`). It shares app.py's one-app-at-a-time lock: a second launch makes the running one open a fresh link. `./run.sh` does the terminal rebuild instead when stdin isn't a terminal and a ledger exists, so cron uses `./gmail.sh`. No user-facing text names a terminal command (use is CLI-free on every OS; install may use one). `tests/test_welcome.py` covers file-name and spending-list cleaning, the HTTP gates, ping, uploads, passwords, Gmail settings and the delete confirmation. `update_statement.py` keeps a per-PDF parse cache in `workspace/.cache/` (key = file bytes + `extract_ledger.py` source + pdfplumber version + the `LEDGER_*_REF` settings; mode 0600; unused entries pruned after each good run; `tests/test_update_statement.py` covers it, the same-minute sort order, own transfers and the `main()` merge).

`app.py` — the app window `./run.sh` / `./run.sh --app` opens: `web/dist/index.html` in the system web view via pywebview (Qt/PyQt6 web view on Linux, `gui="qt"`; WebView2 on Windows; its saved page state lives in `workspace/.app/` on Linux and Windows, macOS uses WebKit's default store). Add statements / Settings open the wizard inside the window; its `Api.call` runs the same `welcome.handle` handlers as the HTTP server (rescanning `Statement/` per call). One app at a time (`only_window`, lock in `workspace/.app/`): a second launch writes `.app/raise` and the open window comes to the front (`bring_forward`). Gmail while the window is open (`start_gmail`): the `--listen` listener with `GMAIL_TOPIC` set, else one fetch at start once signed in (`token.json`); its output goes to `.app/gmail-listen.log` and "Dashboard updated." pushes the new data into the page. No web view → exit 3 and `run.sh` opens the same app in the browser (welcome.py). `tests/test_app.py` covers the lock and raise. `run.sh` (= `launcher.py run`) rebuilds `web/dist` before every launch and reinstalls the packages when the mode's requirements files differ from `.venv/requirements.installed` (written after a good install).

Adding a bank: a module in `workspace/banks/` (`BANK = Bank(...)` + parser, listed in `banks/__init__.py`), a `tests/test_<bank>.py`, and a display entry (name, card colour, logo) in `web/src/lib/banks.ts`. Adding a theme: an entry in `web/src/lib/themes.ts` + optional `[data-theme="…"]` block in `web/src/index.css`.

## Gotchas

- `web/dist/index.html` is generated and holds all the data inline; never edit it. Edit `web/src/`, then `npm run build` (refreshes `web/prebuilt/index.html`) and `build_dashboard.py` (puts the data in).
- Personal data is gitignored (`workspace/*.csv`, `workspace/expected.json`, `workspace/.cache/` (parsed rows per PDF), `workspace/.app/` (the app window's browser storage), `web/src/data/`, `Statement/`, `token.json`, `workspace/.gmail_seen.json`, the env secrets file; `web/dist` via `web/.gitignore`). No personal values live in code, docs or defaults: account refs, `ACCOUNT_LABEL`/`ACCOUNT_HOLDER` (top-bar avatar + greeting) and `THEME` come from the settings file; keep it that way. Passwords: `KTB_PW` (old name `STATEMENT_PW` still read) and `KBANK_PW`. README.md is the user-facing guide (one copy-paste install command per OS, then everything in the app; terminal commands only in an optional table); keep it in sync with the scripts. A global hook blocks Claude from touching env files.
- Ledger CSVs are `utf-8-sig`; columns `Date, Description, Category, Amount, Balance, ID, Bank` (`KTB`/`KBANK`/`Manual`); Amount signed (income +, expense −). `manual_entries.csv` keeps the first five (ID and Bank are set on merge). An old 6-column ledger gets `Bank` on the next `./run.sh`.
- Transaction ID (`workspace/txid.py`, `tests/test_txid.py` covers it): sha256 (16 hex) of `yyyymmdd hhmm <satang>#<n>` (rows of banks other than KTB/Manual get the bank name in front, so a KTB and a KBank payment never share an ID); money out has a leading 0 (`0100` = out 1.00, `100` = in 1.00); `n` = occurrence of the same (minute, signed amount) within ONE statement. The `n` matters: real data has repeated same-minute same-amount transactions (e.g. four 30 baht deposits in one minute), which a plain date+time+amount key would silently drop. Overlapping statements number the same rows the same way, so their copies share IDs. A hash collision raises.
- Directories `Statement/`, `workspace/`, `web/`, `tests/` and `.venv/`, plus `pyproject.toml` and `uv.lock`, are the whole project (`web/node_modules` and `web/dist` are build output; `web/prebuilt/index.html` is build output too but committed on purpose, so users need no Node). The project folder is its own git repo.
- Tests never see real data: `tests/conftest.py` sets `SV_ROOT` (honoured by `config.py` and `launcher.py`; a test-only data-folder override, not a user setting, so it stays out of `.env.example`) to a temp folder before any import, so every data path (settings file, ledger, cache, `Statement/`, `token.json`, `web/dist`, `.app/`) lands there. Keep it that way in new tests.
- `requirements.txt` and `requirements-app.txt` are generated from `uv.lock` (commands under Commands, also run by the pre-commit hooks): never edit them by hand. The ruff pin in `pyproject.toml` must equal the `ruff-pre-commit` rev in `.pre-commit-config.yaml`, and `[tool.uv] required-version` the uv hook rev and CI's setup-uv version: bump them together. Optional: `git config blame.ignoreRevsFile .git-blame-ignore-revs` once that file exists (it lists the ruff format commit).
- `extract_ledger.py` and `banks/*.py` are hashed into the PDF parse-cache key, so any edit to them (a reformat included) makes the next update re-read every PDF once.
- After any change under `web/src/` (or `web/index.html`, `vite.config.ts`), run `npm run build` and include `web/prebuilt/index.html` in the same commit; otherwise users keep running the old page (CI fails on `git diff --exit-code web/prebuilt/index.html` after its build). It must never contain data: the ledger only ever enters through the placeholder.

## web/ (React dashboard)

Vite 8 + React 19 + TypeScript 6 + Tailwind v4 + shadcn/ui (style `base-nova`, Base UI primitives) + Recharts + Motion (`motion/react`). No MUI (replaced by shadcn `Sheet`, `Popover`, `Tooltip` and plain elements). `vite-plugin-singlefile` inlines everything into one offline page (`prebuilt/index.html`, no data; `publicDir` is off). Full design system in `DESIGN.md`.

- All aggregation is in `src/lib/ledger.ts` (`summarize`, `rateTable`, formatters). Components live in `src/components/ledger/`, the setup wizard in `src/components/setup/wizard.tsx`, entry `src/App.tsx` (`/?setup` → `Wizard` alone, else dashboard; `?app` = the app window, `?web` = the browser app, both `HOSTED` in `lib/utils.ts`: Add statements and Settings open the wizard over the dashboard, and no data shows the first-time setup; a page opened from disk shows `EmptyState` and `OPEN_APP` hints). Three tabs in the URL hash (Dashboard, `#plan` Expected Spending, `#custom` labels); the dashboard is one page whose nav rail scrolls to sections (`SECTIONS` in `src/lib/nav.ts`).
- Browser-local state (localStorage): `ledger-label-rules` (Custom tab labels; saving reloads the page), `ledger-expected-spending`, `ledger-theme`, `ledger-seen-rows` (new-row highlight). The `THEME` setting and `expected.json` arrive via `meta` and seed these defaults.
- Styling: `src/index.css` holds theme tokens (light "Daylight" default, dark "Midnight"; violet `--brand` for controls, violet `--income` / coral `--expense` for data, green/red `--pos`/`--neg` for signed amounts) and helpers `.display`, `.eyebrow`, `.pill`, `.num`. Fonts via `@font-face`: Geist, Geist Mono (woff2 vendored in `src/assets/fonts/` with their OFL licence; the `geist` npm package was dropped because its `next` peer dependency pulled ~300 MB of Next.js into every install), Outfit (display/headings, `@fontsource-variable/outfit`). `applyTheme` (`src/lib/themes.ts`, called first in `main.tsx`) sets the Tailwind `.dark`/`.light` class and `data-theme` on `<html>`.
- `src/components/ui/*` is shadcn-generated (`card.tsx` customised); `@/lib/utils` is `cn` (clsx + tailwind-merge). Do not add the npm package `cn`; the shadcn CLI emitted `from "cn"` imports once and they had to be rewritten. The `shadcn` package is not a dependency (its CLI drags in ts-morph, an MCP SDK, …): its `tailwind.css` is vendored as `src/shadcn.css`; add components with `npx shadcn@latest add <name>`. Don't re-add `shadcn` or `geist` to package.json.
- `TxTable` mounts either the table or the card list by media query, never both (rendering both froze the browser), and pages 15 rows at a time.
- Each `build_dashboard.py` run writes `dist/version.js` and `dist/data.js`; no polling: in the app window, app.py calls `window.__ledgerUpdate()` after a Gmail rebuild and the page swaps the new data in (`main.tsx`). A browser tab needs a reload.
- Keep `data-od-id` tags on main regions. Light (Daylight) is the default, dark must keep working.
- Empty ledger is a supported state: `lib/ledger.ts` reads the data from the `#ledger-data` tag at runtime (`null`, the untouched placeholder, = empty dataset) and `App` renders the first-time `Wizard` (app window, browser app) or `EmptyState` (a page opened from disk) when `TX` is empty. `build_dashboard.py` and the install build that blank page without any CSV. Never import `@/data/ledger.json` (it would bundle personal data into the committed prebuilt page), and keep anything that reads `TX[0]`/`META.from` inside `Dashboard`.
